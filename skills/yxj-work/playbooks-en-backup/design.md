# Design Playbook

1. Read the relevant code, task contract and research evidence.
2. Describe the current chain, reusable capability, boundaries, assumptions and alternatives.
3. Define done_when, verification layers, file boundaries and irreversible decisions.
4. Write the design to `.work-docs/tasks/<task-id>/outputs/`.
5. Do not modify project code in the design phase.
6. If research evidence is insufficient, stop at `design_only` or `gather_more`; do not create an execution task.
