x-rail v4 守卫：流程、边界、关键卡点

对应实现：skills/x-rail/extensions/x-run-guard.ts、guard-core.ts、scripts/xr。日期 2026-10-22。
一条原则：还有产出就继续，没有任何产出才停。
产出 = 模型流事件、工具开始/输出/结束、units.tsv 或 ledger.tsv 内容变化。连续 IDLE_STOP_MS（默认 240 秒，可用 X_RAIL_IDLE_STOP_MS 覆盖）都没有产出才中止，并写 handoff.md。

主链路：一次会话里发生什么

主线 停止 等待/提示 记录/修复
会话开始

找 ACTIVE run 并绑定

xr bind --session <当前会话>，核对 workspace / run / session；绑定成功才进入 bound 状态，并提示未完成的 run。

卡点 1 · 绑定：没有 ACTIVE run、被别的会话占用、lease 不对 → 不绑定，全程不自动续跑，只提示原因。
每次开工

核对身份，重置进度计时，启动看门狗

  • 会话 ID 变了 → 重新 bind（generation 递增）；绑不上就清空绑定。
  • lastProgressAt = now，每 5 秒检查一次是否有产出。
卡点 2 · 代次：别的会话接管后，本会话不再推进、不再写状态。
工具执行

先记意图，再执行

工具开始前经 xr event --record 写 op_intent（带 workspace / run / session / generation）。成功结果关闭动作；报错保持未决；被别的扩展阻断且没有执行 → 记 not-started。

卡点 3 · 副作用：未决动作会让 inspect.automation_allowed=false，不自动续跑，也不能 done。
准备收尾

agent_before_settle：逐道门判断

详细分支见下一节。只有通过全部卡点才会注入一条续接消息。

续接消息：运行目录 + 下一步：xr next（当前单元），每轮只注入一次。
结算

agent_settled：只记录真实结局

宿主只提供 aborted；outcome 取 before_settle 当时保存的值，不猜、不补 error 字段。

看门狗中止 → 单独装守卫时写 handoff.md；装了 failover 时交给它处理。
压缩时

只刷新胶囊，不覆盖宿主摘要

刷新 capsule.md 并记录 compaction 事件；摘要仍由 Pi 生成，避免丢掉真实对话。

卡点 4 · 胶囊：刷新失败记 capsule-stale，不拿旧胶囊冒充新状态。

before_settle 决策树（按代码顺序）

前置

是子代理会话，或没有绑定？

是（X_RAIL_SUBAGENT=1 或 unbound）→ 直接返回，什么都不做。
指针

ACTIVE 是否被改到别的 run？

是 → 记 binding-drift，提示“不自动接管”，不跟着换任务。
用户意图

最后一条回答是否在问用户？

是（匹配“请确认/请选择/请提供…”）→ 不自动续跑，把决定权留给用户。
检查器

xr inspect --json（5 秒超时）

卡点 5 · 检查器：无结果、超时、schema 不合法、mode 不是 managed → 写 handoff 并停。
代次

inspect 的 session / generation 与本地绑定一致？

同会话、lease active → 跟到新代次（resume/bind 提代不算故障）。
别的会话 → 记 stale-binding，清空绑定并停。
子代理

有 pending 子代理？

有 → 提示“等子代理回报；不重复派发”，不计数、不续接，等结构化通知。
卡点 6 · 回执：子代理失败/未知时保持 pending，receive 只接受进程退出 0、步骤全完成、会话与产物摘要匹配的回执。
完成

done_met 或“只剩收据问题”？

是 → 调 xr finish 刷新收据；成功提示，失败只告警（收据未更新），不假装完成。
为什么“只剩收据”也收：收据过期只能由 finish 刷新，否则 inspect 与 finish 会互相拒绝，形成死锁。
续跑判定

shouldContinue：五个停/跳条件

条件动作
outcome = aborted / error跳过（错误交给 Pi 原生重试，不在这里补循环）
没有 active run 或 done_met跳过
剩余单元全被 gate 挡住停 + handoff
续跑次数 ≥ 200停 + handoff
连续 3 次语义指纹不变停 + handoff（时间戳变化不算进展）
其余继续
继续前

落盘计数，再注入续接

  • 刷新 capsule.md；失败只记录 capsule-stale。
  • xr guard set 写 guard.json（运行锁 + session/generation）。
  • 写 resume 事件，注入一条 custom_message。
卡点 7 · 计数落盘：写失败 → 停 + handoff，避免内存与磁盘分叉后无限续跑。

关键卡点一览

卡点 1

绑定 / 代次

没有 ACTIVE run、被别的会话占用、generation 过期 → 不自动续跑；同会话提代才跟进。

卡点 2

未决副作用

工具报错不等于没执行。未 xr op reconcile 前 automation_allowed=false，done 也会被拒。

卡点 3

子代理回执

只收结构化通知；要求进程退出 0、步骤 complete、子会话与产物摘要匹配。失败保持 pending，不自动重派。

卡点 4

证据与审查

输入、产物、报告或审查会话任一变化 → stale；review_required 缺有效独立审查不能完成。

卡点 5

检查器

5 秒超时或无合法 JSON → 当作暂停，不当作完成；写 handoff 说明原因。

卡点 6

进度

连续 3 次语义指纹不变，或总续跑 ≥ 200 → 停。只改时间戳不算进展。

卡点 7

空闲

连续 IDLE_STOP_MS 无任何产出 → 中止 + handoff。默认 240 秒，可配置。

卡点 8

暂停记录

handoff.md 只由 xr handoff 在运行锁内写；写不进去也必须停，并记录失败原因。

卡点 9

收据

只有“其余问题都已清零、只剩收据 stale/invalid”时才允许 finish 刷新；其他问题一律拒绝 finish。

边界：守卫明确不做什么

不会

  • 不替你改默认模型、不改 Pi 的 retry 设置。
  • 不在子代理会话里运行（X_RAIL_SUBAGENT=1 直接返回）。
  • 不跟着 ACTIVE 指针换任务。
  • 不自动重派失败的子代理，不自动重放工具。
  • 不覆盖 Pi 的压缩摘要。
  • 不直接写 units.tsv / ledger.tsv / guard.json / handoff.md。
  • 不因为“时间到了”就宣布完成；完成只看 xr inspect。

会

  • 绑定临时 run，并核对 workspace / run / session / generation。
  • 把工具生命周期写成可核对的账（意图 → 结果 → 未决 → 核实）。
  • 在满足条件时注入一条续接消息（带运行目录和当前单元）。
  • 在判据满足时调 xr finish 生成收据。
  • 在停滞、被接管、缺审查、无产出时停下并写 handoff.md。
  • 把“为什么停”写进事件与 handoff，方便下一个会话接手。

配置与文件

项默认说明
X_RAIL_IDLE_STOP_MS240000连续无产出的中止阈值；想更灵敏设 120000，想容忍安静长构建设 600000。
MAX_CONTINUES_WITHOUT_PROGRESS3连续无进展续跑上限，写死在 constants.ts。
MAX_CONTINUES_PER_RUN200单个 run 的总续跑上限，计在 guard.json。
handoff.md—暂停记录：阻塞原因 + 下一条命令 + 恢复说明。
guard.json—续跑计数与语义指纹；只由 xr guard set 写。
