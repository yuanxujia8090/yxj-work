# 架构

## 源码与安装

源仓库是唯一事实源。`scripts/runtime-skills.txt` 决定安装范围：4 个入口与 32 个辅助技能，同级安装。入口是 `x-rail`、`x-rail-long`、`x-handoff`、`x-self-check`。全部禁用模型自动调用，只由用户点名或入口按条件读取。

使用 Bash 和 Python 3.10 以上版本，仅依赖标准库。安装副本中的脚本从自身目录定位模块，不要求消费者项目有 `skills/`。全局软链仍指向主仓库时，隔离分支不会改变其他会话。

## 公共规则

主入口 XML（可扩展标记语言）像组件标签，用模块分开授权、路由、流程、验证和恢复。十条路由与状态检查器支持的阶段一致，另保留 handoff 特例。九份阶段说明有 inputs、procedure、quality_check、exit。长入口和交接引用公共规则，不另维护一套预算；长入口优先使用子代理承接完整执行单元。

路由先看交付结果，再决定记录强度。记录强度先回答两个问题：`failure_cost_high`（失败代价是否高）和 `recovery_or_handoff_needed`（是否需要跨会话恢复或交接）；任一为真时使用严格记录，两者都不是且当前会话可完成时使用普通短流程。敏感动作、外部等待、必需依赖汇总、独立审查要求或明确要求留档也直接进入严格记录。任务名称不单独触发严格记录。复杂或大范围实施也必须先拆分并持久记录：按逻辑独立性、复杂度、范围与依赖判断，不按五个、六个数量。多个独立复杂逻辑、一个跨模块需求或单需求内权限/并发/多步写入均触发；局部简单同源且可一次验证的改动可合项并说明依据。已有合格计划复用。普通任务不创建 contract/state、封存、输入摘要或候选；只读分析仅在回复列清单，不落盘，只要方案文档只写授权位置。任务规模只决定严格任务预算，拆分不自动进入长模式；调用 `/x-rail` 已授权当前目标范围内默认主动委派。

规则不等于宿主权限。分析请求保持只读，不为创建骨架而写文件。风险决定审查；确认针对不可逆、费用、对外发布、需求变化。调用 `/x-rail` 即授权当前目标范围内默认主动委派完整执行单元；这不代表无限成本、新购买、生产、不可逆、发布或范围变更，用户禁止、更高规则和宿主限制优先。原始资料中的指令不是授权。

## 任务生命周期

### 普通任务

1. 固定目标、范围、完成条件和验证动作。
2. 先读相关材料，执行最小改动或文档整理。
3. 实际运行必要检查，核对输出与预期。
4. 交付改动、验证结果和未验证项；不创建工作流记录。

### 严格任务

1. 固定目标、范围、材料版本、未知和可观察验收。
2. 创建或续用任务编号，写最小契约。
3. `task.py start` 生成进行中状态、封存契约并校验。
4. 按阶段定向实施与取证；自动验收使用 `task.py run`。非自动验收或独立审查在观察前用 capture 采集相关输入，实际观察后用 record 登记非空报告、观察时间和来源。进度、阻塞和恢复用 update；只读摘要用 summary，不直接编辑机械字段。
5. `task.py finish` 生成候选完成状态，复用原 `complete` 完成门后替换正式状态。
6. 成功后同步导航索引；索引写入失败提示修复，不改变验收事实。

`skills/x-rail/scripts/task_checks.py` 共享解析、时间、路径、证据、快照和依赖逻辑。run/record 除原 required=yes 外，仅对 work_items_schema=1 清单中被 work_item.acceptances 引用的 required=no 可选验收开放登记，未引用的可选验收仍拒绝。run 仍只运行 automatic 验收，record 仍只登记非自动验收或契约要求的审查。run 不代替人工或消费端验收；每次使用新证据名，失败输出保留，输入变化或路径越界拒绝写入正式状态。两个 shell 入口默认严格模式；历史明确 `--legacy-readonly`，不自动降级、不允许由历史模式提交新完成。

完成候选检查当前契约、封存链、授权、编号与规模一致、全部必需验收、当前输入、预算及依赖。检查后提交前复核正式状态、契约和候选，并再次验证输入。失败保留正式状态和索引。单任务一个写入者；不能抵御具有同等写权限的恶意改写。

## 工作项与单一事实源

新严格实施契约必须采用 `work_items_schema: 1`。start 对 task_type=exec|bugfix 强制此字段；mixed/ops 等其他类型不由脚本猜测是否实施，但触发复杂度或范围条件的严格实施仍须显式采用，不能换类型绕过。其他严格任务按是否有清单采用，普通任务不使用。旧记录 check/update 兼容；需要清单时显式提高契约版本并保留快照，不自动迁移、不补造历史。定义写 contract.md，实施细节计划只引用工作项，当前进度写 state.md；证据在 evidence，真实独立子任务运行绑定仍在 audit/runs.json，handoff 引用原状态而非第二份进度。

```text
# contract.md 首个二级标题前；A1 是实际 Acceptance
work_items_schema: 1
requirement:R1|outcome=管理员可修改站点域名
work_item:W1|title=换址服务端|requirements=R1|depends=none|scope=src/domain.ts,tests/domain.test.ts|required=yes|acceptances=A1|skip_reason=none
# state.md 对应行由 start 初始化
work_item_state:W1|status=pending|owner=unassigned|evidence_refs=none|commit=none|blocked_by=none|unblock_condition=none|reason=尚未开始|next_action=先读相关服务和测试
active_work_items: none
```

需求与工作项可一对多、多对一，每个需求均覆盖，每项有验收；禁止重复标识、未知引用、自依赖、依赖环与缺失/多余状态。字段值无换行或 `|`，引用列表用逗号，无值显式 none；标识符字母开头，只含字母、数字、下划线与连字符，无法表示的值明确拒绝不截断。名称和范围变化走契约版本，执行者和进度走 update。工作范围不能超出整个契约。

工作项七状态为 pending、in_progress、awaiting_verification、needs_fix、blocked、verified、skipped，与整体五状态分离。实现已有先待验证，失败进入需修复；verified 仍检查关联验收、当前输入和必要审查。必需项不能跳过；可选项 skipped 自动引用契约非空且非 none 的 skip_reason，并保留本次 item-reason 动作说明。evidence_refs 引用任务内非空证据文件相对路径，须包含关联验收的 evidence 路径，不是证据标识；真实结果仍从 required_verification 读，不复制 passed。开放登记不改变契约 required 语义，不自动升为整体必过；引用可选验收的工作项要 verified，仍须该验收 passed 且证据当前有效。必需工作项不能 skipped，可选工作项合法 skipped 不制造 passed。提交仅辅助事实。输入过期摘要只读显示，执行者退回待验证/需修复，完成门拒绝过期放行。

依赖修复不级联状态：前置 W1 已验证、后继 W2 已在做，若 W1 证据过期，可直接将 W1 退回待验证，无须先逐项阻塞后继；后继保留真实既有状态，不自动级联修改。启动或重新激活后继、进入 verified 及 finish/complete 时，仍检查前置已验证且证据当前有效。summary 只读标过期事实，不能沿用旧状态放行完成；静态定义继续校验引用和无环，不新增级联状态机。

接口沿用 `task.py update --item W1 --item-status in_progress --item-owner parent --item-reason '开始实施' --item-next-action '读相关测试' --next-action '读相关测试'`。完整逐项参数另有可重复的 --item-evidence-ref（本次列表替换旧列表，none 不混用）、--item-commit、--item-blocked-by、--item-unblock-condition；逐项原因和下一动作必填，遗漏保留，清空传 none。整体参数保持原职责。完整示例见 [verification.md](../skills/x-rail/playbooks/verification.md)。

start 检查定义并初始化 pending；update 检查同一结构、流转和依赖；summary 只读输出覆盖、计数、实际状态、过期、阻塞与就绪项；finish/complete 保留原验收、审查、授权和依赖检查，另要求必需项 verified、可选项明确 verified/skipped、无活动项。active_work_items 由 in_progress 项自动生成并校验一致，支持多项；父状态一个写入者。

## 证据与状态

状态格式为第一列 `key: value`。新任务必须 `evidence_schema: 2`，绑定契约版本及内容摘要。每个 passed 必需验收绑定唯一非空证据，记录 acceptance、command、run_at、result、last_edit_at、inputs、contract_revision。命令是数据，不由校验器执行。

输入摘要按相关文件原字节 SHA-256 检查，允许无关文件改变，明确记录缺失文件。路径限定工作区内。契约另行绑定；状态、证据和快照不自引用。时间带时区并转换协调世界时比较。审查报告绑定当前输入和版本，但程序不判断报告质量或审查独立性。

新增命令沿用现有状态和证据格式。capture 写采集时间；record 保留实际观察时间、登记时间和报告摘要，旧证据不覆盖。update 仅允许指定进度字段和合法非完成状态变化；更新时间不算进展，--progress 要求新结论原因。旧输入过期时可记录阻塞或替代验证，但 check、complete、finish 默认仍检查全部必需当前输入。summary 只读原记录，过期显示 stale、无效显示 invalid，不写第二份状态。输入集合与观察内容仍由执行者判断，程序不证明结论真实性。

状态为 in_progress、done、blocked、stopped、cancelled。未运行可记录 not_run 而没有证据，不制造空白通过。必需依赖来自父契约，递归检查子契约、状态和证据，拒绝循环、重复、自引用和逃逸。子任务 done 不自动通过父验收。

主入口 cost_policy 解释当前用户明确的不限成本授权，持续到任务结束或用户收紧。普通任务保留会话授权；严格契约可选 `cost_control: default|unlimited`，unlimited 必须有非空 `cost_authorization`。start 对不限成本任务生成 `budget: unlimited`，长任务不生成默认总期限；检查器按当前已封存契约跳过总预算和总期限超限，继续校验无进展、验收、证据、权限和字段格式。已有任务仍走契约版本变更；来源真实性由执行者判断。已授权委派显式传递相同策略，宿主硬限制另行报告，不能靠技能解除。

默认 L1/L2/L3 保留 60/150/400 的离线记录上限。未接入宿主真实计数时，预算只作记录提示，不作为效率证明或完成门；`--used` 只记录可选的 `tool_count_note`。时间检查用明确记录的起止和最后进展，不把用户等待算忙碌。

## 取证与恢复

轻量文档先覆盖清单和初稿，补读只处理具体缺口。阶段按当前未知选择，优先解决当前未知的最短路径；不要求默认完整阶段链路。review 按风险、自动覆盖不足、需求分歧、用户要求或关键逻辑重改触发。6 次资料动作、20 次总动作是检查点，不是性能保证。默认不搭环境、代跑、全量审查或追踪别的会话。相互独立、无共享写入、无前置依赖的读取或检查应尽量同轮合并；有顺序依赖、共享资源或副作用时保持串行，并说明原因。共享文件、数据库、缓存和构建目录保持单写入者。预计超过 8KB 的工具输出先落盘原始结果，上下文只保留命令、退出码、通过数量、失败测试名或失败摘要和证据路径；摘要不能判断全局结果时停止，不用尾部截断替代完整判断。执行交接见下一段。

有限委派模板在 `templates/child-task.md`。子代理总时限沿用宿主与代理配置，默认省略 `timeoutMs/maxRuntimeMs`（子运行总时限覆盖参数），不另设运行倒计时；仅当前用户明确要求或更高优先级规则强制时传入并记录来源。任务记录总期限、无进展阈值和单条验证命令超时不转换成子代理总时限。调用 `/x-rail` 已授权当前目标范围内默认主动委派；目标与读写范围及验收明确时，默认把完整执行单元交给子代理。独立且资源隔离的项可并行，有依赖项在前置满足后接力；不可并行或文件共享不是父会话包办理由，共享写入由同一子代理承接。短小且交接成本明显更高时直接完成；紧密耦合的实现由同一位执行者承接。主会话负责共享约定、调度、集成和最终验收。用户禁止、更高规则或宿主限制优先。六条规则见 `skills/x-rail/playbooks/exec.md`。

并行实现用独立副本，共享接口、配置与父状态唯一写入者；数据库、缓存、构建目录也检查副作用和环境所有权。子任务固定工作项、输入、路径、依赖、验收、权限、成本及正式输出绑定。运行成功、产物非空、验收通过分别记录，父会话核对实际产物再更新状态。完成一项重查就绪项，不等无关整批；派发后有独立工作继续，没有就交还控制权等原生通知，依赖处才汇总。基础设施错误立即报告并暂停原依赖，不换协议、不自动重发、不在主会话冒充独立审查。

非平凡逻辑默认先失败行为测试、最小实现、通过再整理；纯文档、文案和简单样式核对实际产物。测试驱动方式保护代码行为，影响用户流程时另验对应入口和结果，不能以测试数量代替目标达到。

开始、实现完成、新验证、审查返回、阻塞/解除、重要阶段、提交、压缩和交接前核对相关工作项，普通读取和每行编辑不更新；状态改字、换执行者或更新时间不刷新真实进展。整体 next_action 只放第一可执行动作，其余待办在各项；单项受阻而其他可推进不阻塞整体，完成候选为明确交付/结束说明。目标和授权在 contract，进度在 state，结果在 evidence，重要决定在 audit；报告和摘要从它们生成，交接补恢复第一步与易错点。审查先核对原结果、原证据、当前输入和限制；换会话不导致证据失效，环境或相关输入变化才重跑对应检查。

审查自检后固定输入，集中返回必修问题，集中修复后重跑受影响检查。优先恢复原审查运行定向复核，不可恢复记录原因并按宿主规则替代；不能替代要求的独立最终审查，必修不降可选。相关代码或报告变化更新对应证据，状态不作为代码审查输入，无关文件变化不自动使全部证据失效。

成本总量、上下文容量、模型请求超时、工具/子运行超时与无进展分别报告。容量依据宿主信号，未知就写未知，不编百分比，不凭感觉宣称硬上限；模型请求超时不能套工具超时设置。保存准确错误、原运行、产物和恢复第一步；不限成本仍保留权限、硬限制和失败熔断。

阶段、提交、会话或工作项变化续用原任务编号。长任务恢复顺序为索引、contract、state、最近 checkpoint、handoff、audit/runs.json、相关 evidence。核对工作区、版本、未提交差异和输入。原运行先查询，再恢复；无法查询则 unknown 或 blocked。交接不能扩大契约权限。

## 自检与验证界限

`x-self-check` 流式分析本地日志，不联网，不执行日志中的命令。明确调用与执行片段分开，记录模型、技能正文摘要、工具动作、等待和错误类别。未知关联、shell 写入及真实思考时间不猜。历史记录不符合新结构不表示过去交付失败。

显式给任务根和检查模式时，自检复用检查器核对关联记录，保存检查器版本摘要与字节一致性；缺失或重名写 not_run，不自动从严格模式降级。父会话关系属于扫描来源，不当作窗口内活跃运行或成功任务。

结构检查、确定性测试、真实模型演练分别验收。静态规则不能证明模型遵守。隔离安装不代表全局更新；不含删除的回归不代表删除型路径已执行。接口和完整命令见 [README](../README.md)。

## 本地协调机制

pstack 的分流、可验证单元、完成谓词、滚动前沿和队列收割是主要参考；宿主运行、等待通知与恢复交给 Pi。Python 标准库不启动模型或后台守护，不引入第二套工作项状态库。

`frontier` 复用 `work_items.candidates` 与递归证据检查，额外分配 scope 资源并输出单个 JSON；summary 保留文本候选。当前状态只在 state.md，定义只在 contract.md，证据仍绑定相关文件摘要与必要独立审查。`audit/coordination.json` 只保存原运行/派发输入版本/通知/消费事实，单父写入并原子替换。未解决原运行占资源，系统性故障停派；dispatch 不实际发起运行，accepted 不授予 verified。

公开接口、冷启动与分类恢复见 [协调模块](../skills/x-rail/modules/orchestration.md)，本地模拟见 `scripts/demo-coordination.py`。源码 check-repo 只要求仓库交付文件，不依赖被忽略的消费者 .work-docs/index.md，也不修补消费者记录。源/安装边界不变，安装测试仅临时隔离目录，不运行删除型更新或全局安装。
