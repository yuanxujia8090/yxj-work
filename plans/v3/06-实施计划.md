# 06 实施计划

> 纪律：
> - 一个修复一个提交；先写测试；每个阶段都可以单独回滚；不推送、不部署、不对外发布。
> - 不改用户已有的修改；不删除旧任务记录和全局技能。
> - 修改 `~/.pi/agent`（settings、providers、extensions）属于本机全局配置，每一项都需要用户批准；仓库内只放源码和"配置补丁说明"。
> - 工作量用 S/M/L 表示相对大小，不给小时数，因为没有可靠依据。

## 3. 测试与评测计划

### 3.1 测试分层
1. **单元测试**：xr 动词、状态推导、幂等、胶囊体量、错误分类表、熔断器。现有测试（task-checks 72、work-items 17、checklist 7、coordination 11、frontier 5、self-check 15）必须继续通过。
2. **故障注入**：P2 的 mock provider 跑 T1–T8。
3. **回放评测**：把真实失败案例转成可以重复执行的场景（见 §3.2）。每个场景跑"旧 x-rail"和"新 x-rail"各至少 2 次，原因是模型输出不确定。
4. **独立审查**：设计审查和实现审查（v3-goal §七.5 的两份清单），由另一模型家族的 reviewer 执行，结果写入 verification-report。

## 5. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 本机 pi 版本没有需要的事件 | P2、P4 无法实施 | P0 检查；升级 pi 需用户批准；退路是只做 P1、P3、P5 加手动 `/x-rail resume` |
| 扩展续跑形成死循环、空烧费用 | 成本 | 每个 run 的续跑和 failover 次数都有上限；无进展检测；`/x-failover off` |
| 跨 provider 回放消息不兼容 | 切换后报 4xx | T3；"先压缩再续跑"退路 |
| deepseek flash 在难题上质量较低 | 返工 | ledger 记录模型；高风险单元由另一家族评审；条件允许时切回 openai26 |
| 全局扩展影响其他 pi 项目 | 行为变化 | 只在当前模型等于 primary 时生效；run-guard 只在有 active run 时生效 |
| skills-main 上游变化 | x-rail 引用失效 | 固定版本 1.3.1；self_check 校验；升级时回归测试 7 个被调用的技能 |
| 用户未提交的改动 | 冲突 | P0.3 先确认；不覆盖 |
| 并行 worker 写入冲突或合并失败 | 返工 | 声明独占文件集；`xr next` 做不相交检查；共享文件归入集成单元串行处理；合并只由主会话串行做，合并后立即验证 |
| 45 min 硬超时仍可能偏短或偏长 | 误杀或空等 | 30 min 软时间盒时汇报进度；回放后按 worker 的 p90 调整 |
| 压缩改用 bai 会产生费用，也受 bai 故障影响 | 成本、压缩失败 | thinking 用 low；摘要上限 3,000 字符；120 s 超时后只用胶囊 |
| 归档 `~/.agents/skills` 下的技能会影响共用这个目录的其他工具 | 其他工具里技能消失 | 07 §1 已提示；脚本有备份和逐条恢复命令；先 dry-run |
| 批次 B 归档后，x-rail 没被选用，原先由全局技能承担的能力出现空档 | 计划、验证类提示缺失 | 守卫要求 x-rail 在加载目录且不带 dmi；先 dry-run；5.10 验收要求新会话中能看到 x-rail；README 中有逐条恢复命令 |
| 指标目标是假设 | 误判 | P6 用实测结果修订，在报告中标注 |

## 6. 完成定义（整个 v3）
