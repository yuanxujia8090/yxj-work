# x-rail v3 方案文档（pi 本地版）

> 范围：只做设计和计划，不含实现代码。
> 输入：v3.tgz、v3-gitlog、pstack.tgz、skills-main.tgz、sessions.tgz（186 个会话文件）、pi-config-redacted.json、pi-ext-skills.txt、run-history-tail.jsonl。
> 时间一律为 Asia/Shanghai（UTC+8）。**假设** 表示有依据但尚未验证；**待确认** 表示需要用户或本机核实。

## 一句话结论

两个真实大任务失败，主要原因不是规则不够，而是以下三点：

- 模型出错后没有人负责续跑和换模型：31 次要人工输入"继续"，openai26 出错后空等合计 6.92 h；
- 长任务的单元太大：worker 30 min 超时后无法接续；
- 压缩后状态靠 4B 模型的摘要维持。

v3 的主线是把稳定性下沉到 pi 宿主层（两个扩展加配置），把状态放到磁盘上，技能层只保留短小的阶段卡。

## 已确认的决定（2026-10-17，详见 05 §8）

| # | 决定 |
|---|---|
| C1 | 学习 pstack：**≥ 5 个单元的大任务走子代理驱动执行**，主会话只做编排、合并和验证；< 5 个单元由主会话执行。一个文件集只有一个写入者，各用独立 worktree，由主会话串行合并。只读子代理并发 **5**，写入子代理 2，合计不超过 5，熔断时减半 |
| C2 | 不用 15 min。单元规模按 ≤ 40 轮、≤ 150K 上下文控制；硬超时 worker 45 min（软 30 min）、reviewer 25 min、researcher 和 scout 15 min |
| C3 | task.py 降为可选检查器；完成判定 = Done 判据 + ledger |
| C4 | 同一模型重试 1 次，之后换模型继续 |
| C5 | RUN.md 用 Markdown；units 和 ledger 用 TSV，由 `xr` 动词写入 |
| C6 | 默认允许在 run 分支或 worktree 上做本地 wip 提交，不推送 |
| C7 | 本机技能清理按 07 执行：保留 50、仅手动 4、归档 12（批次 A，现在做）加 11（批次 B：被 x-rail v3 取代的全局技能，在 x-rail v3 安装并验证后立即做）。x-rail 是唯一来源，x-rail 调用的技能保留。只归档、不删除 |
| 压缩 | 压缩和摘要的 LLM 改为 bai/deepseek-v4.1-flash（thinking low），替换本地 4B；胶囊仍由脚本生成；bai 超时 120 s 时只用胶囊 |
