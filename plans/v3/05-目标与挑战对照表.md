## 4. v3-goal §四（15 个第一性原理问题）

| Q | 回答（对应章节） |
|---|---|
| 1 任务要保存什么 | Intent、Done 判据、Standing orders、units、ledger、decisions、gates、events（03 §3） |
| 2 哪些必须由模型理解 | 目标、Done 判据、当前单元、下一步、Standing orders，都在胶囊里，不超过 2 KB |
| 3 哪些交给脚本 | 状态迁移、依赖、ledger 和 tree hash、体量预算、完成判定（03 §4） |
| 4 哪些规则每次加载 | 入口 ≤ 5 KB，其中硬规则 6 条 |
| 5 哪些按需加载 | 阶段卡（每张 ≤ 6 KB）和 references |
| 6 哪些状态必须持久化 | 03 §3 的全部文件，加上熔断器状态 |
| 7 压缩后怎么恢复 | 胶囊 → `xr status` → 继续 doing 单元（03 §6） |
| 8 弱模型最容易错在哪 | 复杂参数和状态机（37% 拒绝）、长规则、出错后不知道怎么续、子代理 workflow 语法（17 次） |
| 9 哪些操作必须可重复执行 | 所有 `xr` 动词、单元执行（以 scope 为界并有 git 检查点）、failover 续跑 |
| 10 哪些操作必须有顺序证据 | 单元 done 之前必须有 verify（按 tree hash）；Land 之前必须有集成验证 |
| 11 什么时候自动继续 | 有 active run 且判据未满足时；E2/E3 类 provider 错误之后；单元完成之后（03 §5，04） |
| 12 什么时候阻塞用户 | 只有 v3-goal §十一 的 6 类事项，以及剩余单元全部被 gate 阻塞时 |
| 13 什么失败可以重试 | 网络和瞬时 API 错误（同模型 1 次，之后换模型）；unknown 1 次；tool 错误换模型 |
| 14 什么失败越重试越糟 | 余额和账号池问题、4xx 参数错误、逻辑和验证失败、权限错误 |
| 15 核心价值 | **降低完成成本，并提供可靠证据**，而不是强制流程。体现为：Done 判据加 ledger、自动续跑、failover |
