## 目标与设计

统一执行原则，按交付性质选择流程，按真实协调需要伸缩。不设固定“轻量/大任务”双模式，不设工作项或模块数量阈值。pstack 是主要参考，核心机制原则上借鉴；云端、Cursor、Graphite 等用本地宿主能力替换。记录强度与执行组织分开，恢复需求不自动等于长期编排。

复用 contract.md 的工作项定义、state.md 的七状态、evidence 的当前输入摘要和必要审查。Python 标准库负责确定性记账和计算，Pi 宿主负责启动、等待通知和恢复子代理。脚本不直接启动模型，不创建后台守护进程。定义、当前进度和证据各只有一份事实源。

### 来源与适配

- pstack/skills/poteto-mode/SKILL.md：按交付结果分流；复杂任务 figure-it-out；长期项目 Orchestrate；默认新上下文交接，保留宿主恢复约束。
- pstack/skills/figure-it-out/SKILL.md：先定完成条件、验证与单元；隔离并行；逐项验证和最终整体核验。
- pstack/skills/poteto-mode/playbooks/autonomous-run.md：围绕可检查完成条件持续推进，逐项验证，记录转向。
- pstack/skills/poteto-mode/playbooks/orchestrate.md：可计算前沿、滚动派发、完成通知队列、持续接收、版本绑定验证、分类失败与重规划、冷启动恢复、每个写入区唯一所有者。单代理可完成时折叠额外组织，不减少实际验收。
- 本地适配：分支/工作副本隔离，证据绑定相关文件摘要而非只看提交号；Pi 原生异步通知和运行引用；宿主协议优先，运行未知时不重发，不以普通代码失败冒充基础设施失败。

## 实施顺序与验收

### 1. 修正方案与规则

更新 target-architecture.md、migration-plan.md、pstack-comparison.md、delivery.md、DECISIONS.md，撤回与最新原则冲突的“默认关闭子代理/不借鉴编排/15分钟硬上限/task.py可选即可等同证据完成”等设计。保留历史取证和阶段3试点记录，明确静态检查不证明实际提速。

更新入口与相关执行、恢复、工作项说明，保留 XML 结构和十条交付路由，入口尽量维持约5KB。增加统一组织方式的按需说明：普通任务、单目标持续推进、复杂任务定制流程、长期协调；不建立另一套任务状态枚举。修正模块中 not_run/needs_verification/failed 与真实七状态不一致。默认委派遵现有授权；运行时限遵宿主，不凭固定分钟数强杀。

### 2. 让执行前沿成为可重复计算的接口

在现有 task.py 命令体系增加只读、机器可读的前沿查询（建议 frontier TASK_DIR 输出 JSON）。从已封存契约、状态和当前证据计算：就绪、执行中、待验证、证据过期、阻塞及原因、资源冲突、终态。校验每个前置的当前证据及传递依赖；与活动写入范围冲突时不派发；共享目录/父子路径/glob 的不确定重叠保守处理并解释。只输出可派发候选，不自动启动或更改状态，不把工作项全部验证当成整体 finish。

测试边界：task.py 命令行。先写一个能因当前缺失行为失败的用例，再实现并运行同一用例；逐条增加传递依赖、证据过期、阻塞不拖住兄弟项、共享路径和只读查询不改记录等反例。复用 scripts/test-work-items.py 的真实任务夹具与证据工具。

### 3. 持久化接收与失败重规划

为协调任务提供最小持久化结果接收接口（沿用 task.py，新模块按需要抽出）。事件/运行记录只存原运行、工作项、结果引用、发生时输入版本及分类事实；当前工作项状态仍只在 state.md。通知先登记、后核对产物、再 update；重复通知幂等，同标识不同内容拒绝；恢复可列出未消费结果。晚到结果与当前输入/当前运行归属核对，旧结果不能直接放行 verified。

按超时/容量、网络临时错误、工具/参数错误、验收失败、权限与基础设施、未知原因分类给出后续动作；范围过大要缩小或拆分，不原样重发。失败计数来自持久化事实，重规划不能清空历史。重试次数沿用户限制；宿主不允许换模型或重启时明确阻塞。保留错误、运行、产物、工作区和恢复第一步。

接口不替代现有 run/record/update/finish，也不自动把子代理自报当作证据。新增记录绑定到当前 task，拒绝路径逃逸、无效输入、未知项；父记录唯一写入者。无需新数据库或第三方包。

### 4. 可执行的组织闭环

新增按需编排说明及必要模板，写清完整循环：读取前沿 → 在宿主能力与授权内派发 → 完成通知入队 → 安全节点消费实际产物 → 当前证据登记 → 更新原状态 → 重新计算与补位。单项失败只停其依赖，系统性基础设施故障阻止继续扩散。一次代表单元完成后再展开。复杂任务先建验证，逐项接收，最终只补必要集成验收。

提供本地可运行演练，通过公开命令覆盖部分完成、一个失败、独立项继续、重复通知、冷启动恢复、晚到结果与输入变化后拒收、最终完成门；明确模拟宿主事件与真实模型运行不同。更新 README/docs 的实际接口说明，隔离安装中核对新模块与模板可用。

### 5. 验证、独立审查、提交

定向测试随单元运行。最终一次全套测试包括 Python 测试和 shell 测试；不运行删除型安装路径。Python 编译/语法检查代替本项目不存在的 TS 类型检查，若有静态类型工具则实际运行并报告覆盖。check-repo 不应把被忽略的消费者 .work-docs/index.md 当源仓库必需文件：用反例验证新检出仓库和已有任务保护，做针对性修正，不补造用户任务记录。

规范轴与需求轴用两个 fresh 只读审查者，并行检查当前完整工作区相对基线（包括未跟踪源码）；按 code-review 技能输出分别保存。修复阻塞发现并重跑受影响检查，最终核对 diff 和状态后选择性暂存本次实现及既有阶段3工作，提交当前 v3。不推送。
