# yxj-work v2.0 契约质量门与风险分级实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans 按任务逐项执行。每项任务都必须先写失败测试，再写最小实现。

**目标：**在保留 v1.x 历史任务兼容性的前提下，为新任务增加可校验的验收条件、风险分级、确认/审查策略和契约版本关联。

**架构：**继续使用 Markdown 契约和零依赖 shell 校验。新增 `check-contract.sh` 只负责契约结构，`check-state.sh` 继续负责状态和证据完成门，入口技能与 playbook 负责确认和审查策略。

**技术栈：**Bash、POSIX shell 工具、Markdown；不新增第三方依赖。

## 全局约束

- 不迁移历史 `.work-docs/tasks/*/contract.md`。
- 不删除 `done_when`；它保留为兼容摘要。
- 新任务正式完成标准使用 `Acceptance` 下的 A 编号验收条件；state 记录 `contract_revision` 和 `contract_fingerprint`。
- `verification_type` 只能是 `automatic|manual|consumer|external`。
- `layer` 只能是 `syntax/config|static|runtime/local|external|consumer`。
- `risk` 只能是 `low|medium|high`。
- `review_policy` 只能是 `auto|user-confirm|full-review`。
- `risk=medium` 不得自动放行；`risk=high` 必须完整审查。
- 不把自然语言质量评分放进 shell 脚本。
- 每项任务完成后运行覆盖该任务的窄测试，再运行仓库回归。
