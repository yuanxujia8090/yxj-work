## 目标

大任务先拆清楚，再按同一张清单执行、验证和恢复。主会话负责协调，已授权的子代理承担有边界的工作。停止原因必须有实际依据，不能凭“预算快用完了”自行收工。

本版先补任务清单与逐项状态，再优化并行、审查和恢复。不新增通用调度平台，不直接修改全局 Pi 配置。

## 阅读顺序

1. [优化方案](优化方案.md)：需求、设计、文件职责、实施任务及依赖。
2. [验收与证据](验收与证据.md)：反例、自动检查、真实行为验证及交付标准。

本目录是用户授权的方案文档位置。未来实施过程与证据写执行工作区的 `.work-docs/tasks/<task-id>/`，不往方案目录堆运行日志。

## 已确定的选择

| 选择 | 原因 |
| --- | --- |
| 按逻辑独立性、复杂度、改动范围和依赖决定拆分，不设需求数量门槛 | 四个独立复杂需求或一个范围很大的需求，同样需要先拆任务并记录 |
| 复杂实施任务持久记录逐项状态，长模式仍按恢复需求判断 | 清单要能支持恢复，但不因需求数量自动进入长模式；只读分析不落盘 |
| 需求与实施任务分开编号并互相对应 | 一个需求可以拆成多项任务，多个小需求也可能共享一项改动 |
| 计划定义写契约，逐项当前状态写 `state.md` | 复用现有事实源，避免多个进度文件互相矛盾 |
| 保留整体任务状态，新增独立的工作项状态 | 不把“待验证”等子项状态混进现有整体状态枚举 |
| 沿用现有更新、摘要和完成入口 | 不再新增第二套生命周期或后台服务 |
| 拆分后，无依赖且资源不冲突的任务优先交给子代理并行实现 | 避免主会话包揽实现；并发数按实际任务和宿主能力调整，不固定为两条 |
| 用实际限制决定停止，用有效证据决定完成 | 费用、容量、超时和无进展不是同一种限制 |
| 原审查者定向复核，按风险补充独立审查 | 减少重复理解，同时保留当前输入和必要独立性 |

已按推荐选了“任务清单与状态检查优先、运行扩展按缺口补”，因为现有契约和证据机制可直接复用。

## 给实施者的交接

```text
实施前先读本目录两份正文、仓库当前说明及相关代码。
核对当前分支、提交、未提交修改和同范围任务索引，保留已有修改。

按优化方案中的实施清单推进。先完成任务拆分和状态记录，再做并行、
恢复及审查规则。非平凡脚本行为先写失败反例，再做最小实现并验证。

已有计划先核对覆盖，不重新设计。拆分后先找无依赖或前置已满足、
互不依赖且不争用文件或环境的任务，获授权后优先交给子代理并行实现。
选择串行时记录具体原因，不只把子代理用于事后审查。
执行同一目标时续用原任务编号；阶段、提交、会话或工作项变化都不自动建立新任务。

写代码、验证通过、用户流程可用和整个任务完成分别报告。
不把工作项已提交或子代理自报完成当成验收通过。

本方案不是委派、付费模型演练、清理、全局安装、提交、推送、发布或
生产操作授权。执行时依当前用户与项目规则核对权限；审查不授予权限。
运行测试前先核对副作用，涉及删除和覆盖的动作先说明风险并取得同意。

准确记录限制和失败，禁止原样重复失败调用，禁止切换受治理的运行协议。
只运行与改动有关且已获授权的检查，不降低原必过验收来换取提速。
```
