### 需要纠正的两个常见误判

- **“`done` 完全不校验”不成立。** F13 显示首次完成有当前文件摘要与命令摘要校验。真实缺口是：完成后文件再变，状态仍保持 `done`；整体完成判断也不重验（F1）。
- **“`close` 无条件删除 ACTIVE”不成立。** F15 显示有值比较。真实缺口是缺原子性与所有权，不是完全没有检查。

## 2. Pi 1.3.0 提供的宿主能力

来源：`/Users/yuanxj/.hermes/node/lib/node_modules/@earendil-works/pi-coding-agent/dist/core/extensions/types.d.ts`（本机安装的 1.3.0）。

| 能力 | 事实 | 对 v4 的意义 |
| --- | --- | --- |
| `tool_call` | 带 `toolCallId`、`parentToolCallId`；handler 可返回 `{ block: true }` | 可以在执行前登记“意图”，并阻止不允许的调用 |
| `tool_result` | 带同一个 `toolCallId`、`isError`、`content`、`structuredContent`、`details` | 可以配对确认“已返回”，据此区分“已启动未返回” |
| `agent_before_settle` | 事件含 `outcome: completed \| aborted \| error`；可返回 `{ continue: true, entries }` | 普通错误与续跑的统一入口 |
| `agent_settled` | 在“不再有自动重试、压缩、续跑”之后触发，带 `aborted` | 看门狗收尾只能在这里做，不能抢在重试之前 |
| `session_before_compact` | 带 `reason: manual \| threshold \| overflow`、`willRetry`、`signal` | 压缩前刷新胶囊，并能区分“溢出恢复”与“主动压缩” |
| `session_compact` / `session_compact_failed` | 压缩成功/失败独立事件，失败带 `fromExtension` | 压缩失败可以记录，不再静默 |
| `ctx.sessionManager.getSessionId()` | 返回宿主会话标识 | 运行绑定可以包含会话维度 |
| `ctx.getContextUsage()` | 返回 token 用量或 `undefined` | 边界决策可保留现有做法 |
| `pi.setModel()` | 扩展接口返回 `Promise<boolean>` | 切换失败可判定，不靠异常 |
| `session_shutdown` | `reason: quit \| reload \| new \| resume \| fork` | 可以在退出/换会话时留下未决工具记录 |

**仍然未知（必须在实施阶段验证，不能凭类型推断）：**

- `tool_result` 是否在工具被 `block` 时也触发；若不触发，需要 `terminate` 或超时补记。
- 工具进程被外部杀掉时，是否保证有 `tool_result`（预期没有）。
- 子代理子进程是否加载全局扩展；它的 `tool_call` 是否会进入父会话事件流。
- `agent_before_settle` 里 `await` 一个外部进程（`xr inspect`）的实际超时行为。
- `session_before_compact` 里同步调用 `xr capsule` 的耗时上限。

## 4. 缺口清单（按影响排序）

| 编号 | 缺口 | 现状 | 影响 | v4 处理 |
| --- | --- | --- | --- | --- |
| G1 | 完成判断不权威 | `runSnapshot` 只看单元状态；`abandoned` 可让运行“完成” | 误报完成、放弃项被当成交付 | 引入 `xr inspect` + `acceptance.tsv` + `finish.json` |
| G2 | 工具副作用不可追认 | 只记录 `tool_result` 计数，没有意图与配对 | 恢复时可能重复写文件、重复执行命令 | 意图/结果配对，未知即暂停 |
| G3 | 恢复入口分散 | 普通错误、看门狗、边界续跑、压缩各自判断 | 分类遗漏时静默停止，或绕过上限 | `decideRecovery()` 单一入口 |
| G4 | 运行身份不固定 | 每次重读 `ACTIVE`；计数只有 `run_id` | 旧会话接管新任务；换会话清零上限 | `binding.json` + `owner_session_id` |
| G5 | 错误分类有洞 | 断流、裸 502 落到 `none` | 需要人工“继续” | 补样本 + 未知错误显式暂停 |
| G6 | 完成状态不复检 | 已 `done` 直接 `unchanged` | 完成后改坏代码仍算完成 | 完成门重验；`done` 重复调用也复核 |
| G7 | 自动续跑会被人话打断 | 结尾问号即停止 | 模型自问自答就停下 | 只在明确的拍板请求上停；有 gate 默认值时继续 |
| G8 | 压制式验收缺失 | `harness.py --live` 名不副实 | 误以为已做真实回放 | 改名/标注；新增真实宿主本地测试 |
