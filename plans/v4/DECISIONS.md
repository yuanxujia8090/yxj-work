> 状态：**设计决策，未批准实施**。本文件记录方案作者的推荐与理由；用户确认后才进入实施。

## 1. 核心决策

| # | 决策 | 选择 | 理由 | 放弃项 | 重新评估条件 |
| --- | --- | --- | --- | --- | --- |
| D1 | 稳定性归属 | 宿主扩展负责事实与恢复；技能只决定做什么 | 模型不运行时提示词无法生效；v3 已有真实证据 | 用更长的提示词约束模型 | 扩展 API 发生破坏性变化 |
| D2 | 完成判断 | 唯一权威是 `xr inspect`，扩展不再自算 | `runSnapshot` 只按状态；误报完成代价最高 | 保留 `runSnapshot` 作为快速路径 | `inspect` 在真实仓库超过 5 秒且无法优化 |
| D3 | 工具副作用 | 记录 `op_intent` / `op_result`，未配对即暂停 | 重复写文件比停下来更贵 | 只按 `tool_result` 计数（现状） | 宿主能提供事务性工具语义 |
| D4 | 未配对写操作 | 一律 `pause`，不自动重放 | 无法证明写是否生效；重放可能破坏数据 | 自动重试写工具 | 工具声明幂等并可验证 |
| D5 | 只读未配对 | 也 `pause`，但提示可直接查结果 | 读操作风险低，但仍需人工确认上下文 | 自动重放读工具 | 读工具可证明无副作用且可安全重试 |
| D6 | 恢复入口 | 全部经 `decideRecovery()`；看门狗只报告 | 现状多条路径各自判断，会漏接或绕上限 | 各扩展自行处理 | 出现无法用单一函数表达的新失败类型 |
| D7 | E2 语义 | 同模型再试 1 次，之后切换或交接 | 既有决策 C4；实测 E2 多为瞬时抖动 | 直接切模型 | 回放显示同模型重试显著延长完成时间 |
| D8 | 余额/鉴权 | 停止，不重试不切换 | 换模型只会产生新的失败请求与费用 | 继续切备用“碰运气” | 有明确的多账号/多计费策略授权 |
| D9 | 未知错误 | `pause` 并保存原文 | 当前对裸 503、未匹配文本返回 `none`，两边都不处理 | 归入通用重试 | 积累足够样本可稳定归类 |
| D10 | 运行身份 | `workspace + run_id + session_id`，写在 `binding.json` | `ACTIVE` 是工作区级指针，不能证明归属 | 继续每轮重读 `ACTIVE` | 宿主提供原生运行隔离 |
| D11 | `ACTIVE` 定位 | 仅作发现入口；绑定后不再读 | 保留旧习惯，减少迁移成本 | 删除 `ACTIVE` | 所有调用方都支持 `--run-id` |
| D12 | 事件存储 | 扩展现有 `events.jsonl`，不新建目录 | 已有只追加文件；新增文件会增加双状态源 | 新建 `turns/` 与 `ops/` 目录 | 事件量导致解析变慢 |
| D13 | 验收表 | 新增 `acceptance.tsv`，旧表不改 | 0.0.10 已论证；旧运行只读兼容 | 强制所有历史运行迁移 | 旧运行需要批量启用 |
| D14 | 完成收据 | `finish.json` 可重算，摘要变化即失效 | 收据不能变成第二份权威状态 | 用 `RUN.md` 手写“已完成” | 无 |
| D15 | `done` 幂等 | 已 `done` 也复核证据，过期则拒绝 | “完成后改坏文件仍算完成”是已证实的缺口 | 保留 `unchanged` 早退 | 复核成本影响正常使用 |
| D16 | `asksUser` | 只在明确拍板请求或开放无默认 gate 时停 | 结尾问号会让模型自问自答就停下 | 保留宽泛匹配 | 出现自动续跑打扰用户的情况 |
| D17 | 范围 | 只做身份、工具生命周期、统一恢复、完成门 | 当前短板是闭环证据，不是功能数量 | 同时做预算收尾、第二模型 | 四项全部通过真实宿主验收 |

## 2. 明确不做（本轮）

| 项 | 原因 |
| --- | --- |
| 预算 70% 自动收尾 | 缺统一墙钟/成本计量；自动停止会改变任务范围 |
| 第二备用模型 | 不是已证实的根因；增加路由与费用复杂度 |
| 提高重试/续跑/并行上限 | 问题是边界与证据，不是吞吐 |
| 自动重派子代理 | 与“先查原运行”冲突，可能造成双写 |
| 真实模型付费回放 | 需要单独授权与预算 |
| 个人 HOME 安装/软链接切换 | 会立即影响其他会话；须单独确认 |
| 旧 `task.py` 迁移 | 两套协议边界清晰，混迁扩大风险 |
| 重写 `xr` 或换语言 | 现有脚本可复用；重写不能证明更可靠 |

## 3. 行为变化（用户可感知）

1. **结束更严格**：所有单元 `done` 不再自动等于任务完成；必须有验收关联与有效证据。
2. **`done` 可能被拒绝**：完成后文件变化，再调 `done` 会要求重验。
3. **余额/鉴权错误停止**：不再自动切备用模型。
4. **未知错误暂停**：会明确提示，而不是静默结束。
5. **旧运行只读**：`mode=legacy` 不自动续跑；需要显式接入。
6. **边界检查有额外开销**：每次 settle 启动一次 `xr inspect`，限时 5 秒。
7. **绑定冲突会提示**：另一会话占用同一运行时，不自动接管。

## 4. 已知限制

- 检查器能验证“证据存在且对应当前版本”，不能验证“需求语义被真正满足”。
- 事件追加只保证单行不撕裂，不保证多进程顺序。
- 子代理是否进入父会话事件流未验证；在验证前，子代理的未配对工具只能保守处理。
- `binding.json` 不能防止有同等写权限的进程伪造；它解决的是误接管，不是安全隔离。
- 5 秒超时是初始策略值，不是实测性能。
