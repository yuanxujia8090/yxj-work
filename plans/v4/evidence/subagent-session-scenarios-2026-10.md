## v4 机制分层

- **已有任务机制：**工作项、依赖前沿、原运行登记、通知接收、失败分类、版本/输入绑定和暂停恢复；这部分比 v3 只依赖会话提示更可追溯。
- **本次加强的提示规则：**代理名发现、单代理/工作流二选一、代码块存在、工作流子项字段层级、管理操作与运行控制区分，以及错误后的分支处理。
- **本地机械检查：**下方 `test-subagent-scenarios.py` 核对矩阵场景 ID、每类覆盖状态、关键模板规则和风险边界。它是文档一致性检查，不调用 Pi、不解析真实工具参数，也不证明模型行为。
- **未覆盖的宿主门：**Pi 对 agent 名、workflow 脚本、参数 schema、并发上限和 async run 控制的真实校验。本地静态材料不能取代隔离 HOME、本地假模型的 Pi 集成回放；本次不为测试安装或改宿主。

## 与 v3 的对比

任务拆分、前沿、原运行占用、接收与证据绑定方面，v4 有实质增强。子代理调用协议错误方面，v4 从“泛化遵循宿主协议”细化到按失败类别的前置核对，属于规则层改善；但没有运行时参数生成器或宿主前置拦截，不能判定真实发生率已下降。当前结论是“设计覆盖提升，真实 Pi 调用效果未验证”，不是整体效率或可靠性优于 v3。
