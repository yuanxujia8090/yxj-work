# x-rail 任务闭环

日期：2026-10-22。以下为 v4 接口与行为要求，均待实现或重新验证。

## 一条完成链

像构建产物必须对应当前源码：昨天的绿色检查不能替今天的改动背书。x-rail 的链路是：用户要求 → 可验收工作项 → 当前输入与产物 → 实际证据 → 最终集成 → 当前完成检查。

`xr inspect --json` 是唯一完成判断入口。JSON（JavaScript Object Notation，一种结构化数据格式）便于扩展直接读取结果。`xr done`、`xr finish`、任务守卫和自检复用同一套判断；它们可以检查不同范围，不能实现相互矛盾的规则。

## 用户入口与记录强度

入口仅保留：交付类型、普通/持久两种记录路径、当前阶段需要读取的卡、权限边界和交付要求。

- 普通任务：直接先读、执行、验证、交付，不调用 task.py。
- 持久任务：只用 xr。进入条件是恢复、依赖与证据需要，不按文件数量、单元数量或固定轮数分类。
- 旧 contract/state 工具只服务旧任务的显式命令，不进入新任务路由。现有旧模式不删除，不自动迁移。
- 不机械调用 grilling 等访谈；能读到的事实自己查。只有不可逆、花钱、对外发布、范围变化才需要用户拍板。

初次绑定在任务创建后当场完成，不要求重启 Pi。增加 `/x-rail-run attach <run-id>` 命令，由任务守卫取得宿主真实会话标识后执行绑定；它只绑定和显示恢复摘要，不触发模型请求。新会话不能仅因 ACTIVE 有值就自动接管。

## 源数据与有效性

沿用现有文件，新增字段须兼容读取旧记录。所有任务权威状态写入均在现有 `run_lock` 下；仓库级 ACTIVE 更新另有仓库锁。扩展通过 xr 命令写事件，不与 Python 各自无锁追加同一日志。

| 数据 | 新设计规则 |
| --- | --- |
| `RUN.md` | 阶段为 planning/executing/paused/finished；显式转换有事件。权限来源可引用用户消息，不靠关键词推断授权 |
| `binding.json` | 含 schema、规范化 workspace、run_id、session_id、generation、lease。generation 是每次绑定或接管递增的代次。lease 只表示 active/paused/released，不证明旧进程已终止 |
| `units.tsv` | 保留 id、依赖、读入范围、独占输出范围、验收命令与状态。工作项种类不自动决定模型或委派 |
| `ledger.tsv` | 每次尝试单独证据路径；绑定输入和输出文件清单及内容摘要、命令摘要、报告摘要、退出码、观察时间、证据种类和实际来源 |
| `acceptance.tsv` | 每条验收含可观察要求、用户来源、覆盖工作项。缺覆盖或来源变化拒绝完成 |
| `events.jsonl` | 统一外层 schema、event_id、时间、workspace/run/session/generation、type、detail；工具和异步执行者标识在 detail 中 |
| `finish.json` | 绑定需求、工作项、账本、产物与任务修订版本；后续任一相关变化失效。只读 inspect 重新核对，不凭文件存在认定完成 |

复用现有 `dispatch_epoch` 表示任务修订版本；它和会话绑定 generation 是两回事，不再新增一个同义版本字段。

证据文件写到 `notes/verify-<unit>-<attempt>.log` 等唯一新路径，拒绝覆盖。失败结果也保留。只执行过一次但仍对应当前输入、命令与报告摘要的通过证据可复用；报告被改写、依赖内容改变、原通过来自不同命令、匹配范围的新增或删除都使证据失效。

需求来源优先保存本次用户要求的只读摘录及宿主消息定位；来源是会话引用时，不能只检查引用格式就当作已验证来源。暂无法访问原消息的旧引用标为“来源待核实”，禁止自动完成。检查器能证明已声明需求的覆盖，不能证明自然语言需求已被穷尽；该项仍由计划核对和独立审查承担。

### 非自动验收与审查

需要人工观察、外部报告或独立审查时，使用同一账本，不新建证据系统。增加：

```text
xr evidence record UNIT --kind observation|review --report PATH --inputs PATHS --observer SOURCE --record SOURCE
```

PATH 必须位于当前仓库或运行目录的允许范围；命令保存报告和输入摘要，记录观察者及来源。登记只证明材料被绑定，**不证明内容正确、审查独立或具有授权**。独立审查要求有实际不同执行会话/运行标识、报告及其覆盖版本；自报不同姓名不算独立。

工作项验收类型在 `plan add` 中通过 `--verify-kind command|observation|review` 指定，默认 command；command 才必须有 `--verify`。所有类型的当前有效性由共享检查函数判定。最终 integration（集成工作项，即核对整个交付结果的那一项）也可组合命令与观察证据，不强迫纯设计交付伪造代码测试。

## 当前可做事项与接收

当前 `ready` 仅看前置 done 的实现必须改为递归检查前置的当前有效证据。过期前置挡住后继启动和最终完成，独立分支照常推进；不批量篡改所有后继历史状态。

`xr next` 继续承担选择并认领；没有安全候选就返回原因，不能把空列表当完成。总并发 5、只读最多 5、写入最多 2 是本地默认上限，实际还要取宿主/当前授权允许的较小值；不再读 `X_FAILOVER_STATE`。重叠写入与“写入对方读入”都互斥，状态未知的旧写入继续占用范围。

委派与结果接收复用 Pi 子代理能力；不建第二个后台调度器。父会话按当前依赖选择工作，宿主完成通知到达后及时接收。持久接收最小接口：

```text
xr receive UNIT --receipt PATH --record SOURCE
```

receipt 是任务守卫或宿主查询保存的结构化回执文件，含子 run/session、启动调用标识、状态证据路径、输入摘要、输出路径与摘要。`xr receive` 核对回执归属与当前输入，保存不可变接收事实。相同事件重复接收不产生第二次完成。接收不自动授予 verified/done；还需实际验收。

异步回执只证明已启动时记为 pending；宿主终态、进程终止与产物接收分别记录。已知成功终态才能验收其结果；失败后有部分产物也只能逐项核实。活跃时续原运行；终止后接收已有结果再规划剩余；未知时保持阻塞，不重新派同一范围。父会话不靠 parentToolCallId 猜跨进程亲缘，使用明确的子运行标识。

## 工具现场与不确定副作用

副作用就像点击支付后页面断网：不知道服务端是否扣款时，不能直接再点一次。这里把写文件、命令、提交、外部请求统称为可能改变状态的工具。

增加 `host-events.ts`，由任务守卫独立加载：

1. 工具执行前，在 `tool_call` 记录 op_intent，标识为 session + toolCallId；记录工具名、参数摘要、父调用标识。原始参数可能含凭据，不写入通用事件日志。
2. 只对白名单中的纯读取工具标明 readonly；任意 shell、自定义工具、子代理启动默认可能有副作用，不尝试靠命令字符串证明安全。
3. `tool_result` 可补真实结果和启动回执，但不独自关闭动作。`tool_execution_end` 记录终态并关闭；本扩展主动 block 时也记录明确 blocked 结果。需要覆盖其他扩展先行阻断和抛异常的事件顺序。
4. 返回 isError 只能证明工具报错，不能证明没有写入。可能有副作用的错误记为待核实，暂停该工作范围，禁止自动重放。
5. 意图存在而无结束、进程崩溃、日志半行或中间损坏均视为不确定；暂停自动推进与完成，显示具体动作。
6. 使用 `xr op reconcile OP --resolution completed|not-started|failed --record SOURCE` 保存现场核实。completed 只解除“结果未知”，不替代验收；failed 保持对应工作项阻塞。未知不提供跳过开关。

所有扩展写事件通过 `xr event --record PATH`，record 文件来自本进程私有临时目录，内容由命令校验；带 binding 代次，陈旧会话写入拒绝。该子进程执行不再经过模型工具，不产生递归工具事件。身份检查与事件追加共用运行锁。

内部检查和最终 finish 由扩展直接调用，不套一层模型 bash 工具。这样在所有工具结束后检查，不会被“当前 finish 命令本身还是一个未结束工具”永远挡住。模型可以调用只读 inspect，但只有结算后的检查能用于自动收口。

事件记录不是事务系统：无法保证外部动作恰好执行一次，也无法还原未被观察到的外部效果。完成检查拒绝不确定，恢复通过现场证据继续。

## 权威检查结果

保留现有字段，增加明确的身份、有效性和等待原因；版本仍为 1，新增字段向后兼容，类型客户端必须实际校验而非直接强转。

```json
{
  "schema_version": 1,
  "mode": "managed",
  "run_id": "20261022-1200-example",
  "phase": "executing",
  "automation_allowed": true,
  "done_met": false,
  "ready": ["implement"],
  "doing": [],
  "blocked": [],
  "stale_units": [],
  "unresolved_ops": [],
  "pending_workers": [],
  "acceptance_status": {"total": 2, "covered": 1},
  "binding": {"session_id": "example-session", "generation": 2, "lease": "active"},
  "receipt_status": "missing",
  "reasons": ["第二条验收尚未覆盖"],
  "truncated_tail": false
}
```

`mode` 可为 managed/legacy/invalid，分别是可管理、旧格式、结构无效；`receipt_status` 可为 missing/valid/stale/invalid。`done_met` 只回答产物和证据是否满足全部条件，`automation_allowed` 还需阶段与绑定有效，不能相互替代。

完成必须同时满足：

- 有已确认来源的验收要求，逐项覆盖且当前证据有效。
- 所有必须交付的工作项都已验收；abandoned（放弃）不是 done。被正式替代的历史工作项需要明确替代关系与决策依据，替代项覆盖原验收；无替代关系的放弃阻止完成。
- 前置证据当前有效；最终集成已验收，必需的独立审查覆盖当前最终版本。
- 无未知副作用、未接收终态的执行者、开放权限门、损坏日志或无效绑定。
- 收据生成前在同一运行锁下重检；文件变动中无法得到稳定摘要则拒绝，不能承诺抵御同权限外部进程恶意竞态。

成功执行 inspect 的退出码是 0，表示拿到有效检查结果，**不代表任务完成**；invalid 退出 2 并带结构化原因。调用超时、无效输出、未知结构均由扩展按暂停处理。inspect 不运行验收命令，不修改状态。

## 暂停、接续与取消

现有 `pause/resume/bind` 保留并加强：

- 命令读取 `--session`，其次 `PI_SESSION_ID` / `XR_SESSION`；自动化绑定缺真实标识即拒绝。显式人工离线记录可用 local，但不能自动接管。
- `xr init` 不覆盖已有活动指针；有旧任务时明确引用现有运行，或先显式暂停/释放。指针更新使用仓库锁。
- `/x-rail-run attach` 只接当前会话新建或已显式授权接续的运行；其他活跃会话拥有的运行拒绝接管。
- `resume --take-ownership` 需要旧会话/执行者已停止或明确移交的证据，不因 lease=paused 就推定所有子任务都停止。显式授权同范围接续即可继续，不额外反复问用户。
- 所有扩展调用捕获 `{workspace, run_id, session_id, generation}`；等待 inspect/capsule 后再次校验。新输入、中止、切模型、切会话、关闭会话使旧代次失效。
- `agent_before_settle` 保存结局：completed 可判断任务继续；error/aborted 不返回 continue。`agent_settled` 核对缓存结局与最新取消状态，完成暂停记录；若结算前处理器被取消绕过，在 settled 补写中止现场。
- 暂停先保存权威阶段与事件，再生成 handoff/capsule。落盘失败明确报告具体路径与错误，不宣称已保存；保持不继续。

交接给出：准确 repo/run、最后有效证据、进行与未决事项、原始错误引用、授权边界、下一条**带 repo/run 的实际命令**。胶囊为可重建摘要，不能替换整个 Pi 压缩摘要；使用宿主提供的补充方式保留对话约束，补充接口若不可用则只附路径，不返回仅含任务胶囊的自制 compaction。

## 任务级停止规则

继续只用于“模型正常结束但任务尚有可做事项”。重试错误、重放工具、重派未知子代理都不属于继续。

语义进度摘要只包括工作状态变化、当前有效证据、已接收产物和已解决依赖；排除 updated、纯时间戳、重复日志和没有内容变化的重复 done。连续三次相同进度停止诊断；总续跑 200 次上限跨会话保存。真实用户等待、宿主活跃执行者等待不累加无进展次数。

同一绑定若在正常结束时满足全部判据，任务守卫调用 finish 并生成当前收据；失败转暂停。finished 后相关文件变化时 inspect 显示 stale，需显式恢复、补验收，不能继续沿用历史“完成”。
