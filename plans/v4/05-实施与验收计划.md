# 实施与验收计划

> **执行者要求：** 本文件是任务清单；逐项实施、每阶段先新增能失败的测试再改实现。先复核本文与同目录 [总设计](02-总体设计.md)、[任务闭环](03-x-rail任务闭环.md)、[模型插件](04-Pi模型恢复插件.md)，不从 v4-old 复制代码。

**目标：** 在隔离工作区交付独立可用的任务闭环，以及可选且独立验收的 Pi 模型恢复插件。

**架构：** 任务事实由 `xr` 与独立任务守卫拥有；模型请求重试交给 Pi，插件只配置可选的每请求模型路由。两个产物无共享状态、无相互依赖。

**技术栈：** 现有 Python 3 `xr`、Pi 1.3.0 扩展与 TypeScript、Node、现有 Pi 生命周期假模型。首阶段实测工具链，不升级宿主、不新增第三方依赖。

## 全局约束

- 仅在 `.worktrees/v4` 工作；不更改 v3 或任何 `~/.pi`/`~/.agents` 安装。
- 不覆盖用户文件、运行数据、历史证据或旧方案；旧接口需显式兼容。
- 不默认启用模型链，不改个人 settings、真实模型、退避或空闲超时。
- x-rail 不读取模型插件配置/熔断状态；插件不读取 `.work-docs`，不推进任务。
- 使用真实 Pi + 隔离临时配置 + 本地假模型；禁止远程连接与收费验证。
- 静态类型、单元回放和宿主生命周期的证据分开报告；任何一种不冒充其他层通过。
- phase 是明确的工作阶段；本文件每任务的输入/输出/检查才决定前置，不以章节先后猜权限。

## 阶段 A：宿主能力与独立加载门

**输入：** 本机 Pi 包和现有 `test-run-lifecycle.mjs`。

**做：** 给假模型探针增加：Pi retry 开启、请求失败后第二请求、扩展改写 `message_end`、计数工具、手动模型选择/取消、无凭据、无模型、虚拟模型查找。建立单独最小 `x-run-guard.ts` 入口、最小独立插件入口的显式加载探针，不先搬 failover 实现。

**检查：** `HOST_PROBE_PI=<本机 Pi 绝对路径> node scripts/test-run-lifecycle.mjs` 输出每个宿主行为和本地请求数；`scripts/typecheck-extensions.sh` 可在现有依赖已安装时运行，不以自动联网安装补缺。

**通过后才进入 B/C：** 至少能确定内建重试顺序、失败消息改写顺序、取消请求数、工具结果保留、虚拟模型注册及缺失凭据行为。记录实际 Pi/子代理版本。

**若改写未被 retry 读取：** 将错误兼容标记为不可实施功能，插件只用 Pi 原生分类，暂停后续插件行为，不转向自造重试器；任务系统 B～E 可独立继续。

## 阶段 C：工具事实、接收与完成门

### Task C1：工具生命周期

**文件：** `host-events.ts`、`x-run-guard.ts`、`run-files.ts`、`scripts/fixtures/run-lifecycle/observer.ts`、真实探针。

- [ ] 先增加真实 Pi 反例：成功、副作用后 error、宿主阻断、外部异常、中止、无结束事件、事件日志损坏；为每个 toolCallId 断言意图与结束配对。
- [ ] 使用 `tool_call` 先记 intent；成功、error、blocked、拒绝和异常用宿主真实结算事件补 outcome。只把明确纯读取白名单归 readonly；shell 默认可能有副作用。
- [ ] 事件包含当前 generation；关闭/重新绑定后的延迟结果不能更改新 run。
- [ ] 在任一可能产生副作用的结果未知场景，assert inspect 与 finish 都拒绝，守卫只暂停。
- [ ] 以真实 Pi 假模型运行生命周期探针；只对本地夹具计数工具断言调用总数为 1。若宿主会重放，先加执行前阻止门。

### Task C2：子代理通知和接收

**文件：** `host-events.ts`、`xr`、宿主 fixture。

- [ ] 模拟“启动成功但子任务未结束”，验收不得通过、范围仍占用。
- [ ] 模拟终态成功并送达重复通知，接收事实只出现一次；子 run/session 与启动 receipt 必须匹配。
- [ ] 模拟部分产物失败、终态缺失、子进程停止但状态未知；都不自动重派同一写入范围。
- [ ] 子会话虚拟模型加载单独归 Task D；本项只验收 x-rail 接收及真实执行者状态。

### Task C3：统一检查与收据

**文件：** `xr`、`test-xr.py`、`x-run-guard.ts`。

- [ ] 覆盖 done 后产物改变、放弃无替代、过期前置、覆盖不完整、损坏事件、开放门、子代理未决、审查过期、收据陈旧/损坏。
- [ ] `inspect` 只返回有效结构与退出码：0 有有效结果，2 无效 run；有效但未完成仍为 0 且 `done_met=false`。
- [ ] `done` 与 `finish` 复用同一有效性检查；finish 在持锁下复查后写不可变版本收据；后续输入改变会显示 stale。
- [ ] 扩展用运行时结构校验检查 inspect JSON；命令不存在、超时、坏 JSON 和未知 schema 都保存暂停，不能判断完成。
- [ ] 修改已有 `scripts/test-xr.py` 运行测试并确认错误状态码和 stdout JSON。

### Task C4：结构化观察与审查

- [ ] 验证通过 path 和摘要保存新的人工观察报告；拒绝运行目录和仓库外任意路径、空报告和覆盖旧报告。

## 验收矩阵

| 关卡 | 输入 | 通过行为 | 不能声称什么 |
| --- | --- | --- | --- |
| 任务单装 | 本地 Pi + 临时 run；未装插件 | 可绑定、推进、检查、暂停与恢复 | 模型能够自动转移到备用模型 |
| 插件单装 | 本地 Pi + 临时配置；无 x-rail | 指定 retry 路由有效，普通模型不受影响 | 任务完成与工具副作用安全 |
| 组合 | 同一 Pi 任务与虚拟模型 + 假模型 | 模型内建重试、任务结算各自只有一个责任方 | 真实网关可靠性或业务正确性 |
| 工具副作用 | 成功 / 错误 / 阻断 / 终止缺失 | 确认结果或停下核实，不盲目再执行 | “exactly once”（外部动作恰好一次）保证 |
| 依赖前沿 | 前置证据当前与过期两种版本 | 当前通过才释放后继；独立项可继续 | 自然语言需求绝对无遗漏 |
| 压缩恢复 | 溢出、手动压缩、压缩失败 | 原摘要保留，capsule 作为补充，失败有记录 | 任意 Pi 版本与交互配置都等价 |
| 暂停/取消 | Esc、中途新输入、换会话、检查等待 | 旧 generation 不发请求、不写状态、不恢复任务 | 所有宿主外杀进程一定留最后瞬间事件 |
| 兼容安装 | 临时隔离 HOME 和现有旧清单 | 新清单独立；重复导出拒绝；来源可核对 | 用户 HOME 安装行为已经生效 |

## 收口与新增决定

先证明任务闭环和插件链路可独立运行，再组合。任一阶段的首要安全检查失败就停该分支，保留测试、错误输出和工作区差异。不要清理复现实物。代码实现阶段不得借机合并 v3、修改宿主配置或扩展用户目标。

## 子代理失败与无流处理（2026-10-22）

- 失败不自动重派：`xr receive` 要求 `state=complete`、进程终态 observed、所有实例 `exitCode=0`、步骤全 complete；否则拒绝接收，worker 保持 pending。`pending_workers` 非空会阻止 verify/done、`automation_allowed=false`，守卫只提示等待、不派发。`stages/execute.md` 明文“禁止自动重派”。
- 看门狗改为**一条原则**（不再分层设阈值）：只要还有产出就继续等；连续一段时间**任何产出都没有**就停。
- 产出包括：模型流事件、工具 start/update/end，以及 `units.tsv` / `ledger.tsv` 的内容变化（每 5 秒比对一次指纹）。
- 阈值只有一个：`IDLE_STOP_MS`，默认 600000 毫秒（10 分钟），可用环境变量 `X_RAIL_IDLE_STOP_MS` 覆盖；不再有“240 秒静默 / 50 分钟工具 / 60 秒宽限”三套数。
- 不以“任务总时长”判断：长而健康的任务和卡死任务的总时长无法区分；任务时长更适合做预算提醒，不适合做中止。
- 证据：`node skills/x-rail/extensions/failover.test.ts` 通过（新增 watchdogDecision 四态断言）；`scripts/test-run-lifecycle.mjs` 29 项通过；`scripts/simulate-v4.mjs` 20 项通过；`test-xr.py` 40 项通过；check-repo passed。
- 未验证：真实静默到 `IDLE_STOP_MS` 才中止的路径（未跑满 10 分钟）。
