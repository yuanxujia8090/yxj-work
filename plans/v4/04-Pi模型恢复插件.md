# Pi 模型恢复插件

日期：2026-10-22。状态：独立子方案，能力探测后实施。Pi 插件即由宿主加载的独立扩展包；此处不新增常驻服务。

## 目的和独立性

像请求拦截器：同一业务可以装，也可以不装。插件只解决“这次模型请求因暂时故障失败，宿主重试时选谁”，不接管业务工作。

独立产物目录：`plugins/pi-model-recovery/`。Pi 扩展清单只加载 `index.ts`。对用户暴露一个可选虚拟模型 `model-recovery/auto`；名称不包含 x-rail，不安装或修改任务技能。

独立性验收：临时工作目录没有 `.work-docs`，只加载插件即可完成错误兼容和模型切换；反过来，x-rail 只加载任务守卫也必须正常工作。二者不导入彼此，不读取彼此状态，不要求互发自定义事件。

## 只补宿主缺少的部分

Pi 1.3.0 已提供：可取消的重试退避、失败回答的模型上下文处理、每请求选真实模型、会话分支状态、实际回答模型记录。插件只增加：

1. 用户明确配置的模型顺序与短暂冷却。
2. 少量已知中转网关的暂时故障兼容。
3. 无真实请求的状态说明与配置预检。

不使用 setModel 加 triggerTurn 模拟用户继续，不提供独立重试定时器、主动付费探测、全局熔断文件、自动工具重放、通用错误文本修复器或摘要成本优化。

## 配置与启用

不假设 Pi settings 支持任意插件字段。插件自己的非敏感配置放在其独立配置路径；`PI_MODEL_RECOVERY_CONFIG` 环境变量可显式指定，默认读取当前 Pi agent 数据目录下 `model-recovery.json`。默认路径解析使用宿主公开目录能力，不能写死个人 HOME。插件只读配置，不创建或修改它。

```json
{
  "schema": 1,
  "chain": [
    {"provider": "local-a", "model": "fixture-a"},
    {"provider": "local-b", "model": "fixture-b"}
  ],
  "cooldownMs": 600000,
  "gatewayCompatibility": true
}
```

以上都是本地测试模型名，不是线上默认链。生产链须由用户明确选择，配置不含密钥，使用 Pi 原有凭据。首版支持 1～3 个去重后的真实模型；各模型必须在目录可用、具备凭据并符合宿主允许范围，不能路由到另一个虚拟模型。

- 配置缺失：不注册虚拟模型，显示“未配置”；普通物理模型不受影响。
- 配置结构无效或链中模型缺失：明确报配置错误，不偷偷选择替代模型。不能用非空断言假定 `find` 一定成功。
- 插件加载只提供选择项；只有用户主动选 `model-recovery/auto` 后才生效。不改 defaultProvider/defaultModel。
- Pi 的 retry.enabled/maxRetries/baseDelayMs 是宿主配置，插件不私自修改。状态命令显示它是否启用及是否足够访问配置链；首版建议 maxRetries = 链长减一、baseDelayMs = 1000，仅作为待用户明确应用的配置建议。
- 宿主重试次数不足时按现有上限运行，清楚说明覆盖范围；次数更多也不允许链尾无限重复请求。
- 不改变 httpIdleTimeoutMs。超时交给 Pi；调低阈值需要思考模型静默行为证据和单独配置决定。

增加只读命令 `/model-recovery status`：显示配置路径、有效链、当前虚拟选择、分支冷却与宿主重试设置。查询本身不发任何模型请求。

## 错误边界

仅处理实际失败的 assistant 消息，且当前会话选择本插件虚拟模型。普通回答中出现 401、503 或余额等字样一概不作为故障。

| 错误 | 插件行为 | 最终责任 |
| --- | --- | --- |
| 宿主已认识的断流、502/503、timeout | 不改原文；在宿主判为 retry 后按暂时错误选择后继模型 | Pi 控制重试次数与等待 |
| `账号池暂无可用账号`、`gateway_concurrency_limit`、`The service is busy`、`Upstream stream ended prematurely` | 确认不是鉴权/余额错误后，保留原文并附可识别暂时故障标记 | Pi 仍控制是否重试 |
| 鉴权、余额不足、额度耗尽、权限错误 | 不改写、不切换；不通过备用模型绕过费用/凭据问题 | 宿主结束，用户自行处理 |
| 未知错误 | 原样交给宿主，不扩大识别；宿主最终结束时插件也结束 | x-rail 若存在则任务暂停；普通对话显示错误 |
| 上下文溢出及压缩后的 retry | 沿用失败模型与思考档位，让宿主处理压缩；不消耗模型故障切换链 | Pi 的上下文恢复 |
| 路由自身失败、配置缺失、连接前失败 | 保存原始来源，按宿主实际结算行为结束 | 能力探测覆盖，不能假定必有 failed.message |

错误改写只附加兼容标记，不删除原文；记录原始错误摘要和改写原因。拒绝“任意错误统一加 overloaded”，否则未知错误和余额问题会被错误重试。

## 每请求选模型

分支状态使用宿主保存的 JSON 对象：`schema`、`activeIndex`、`cooldownUntil`、当前故障链已尝试模型。只在发生实际变化时返回新状态；`direct` 不写状态。进程不创建第二套会话状态文件。

| 请求原因 | 行为 |
| --- | --- |
| user，新用户消息 | 冷却已过可重新尝试主模型；否则沿用当前可用后备。开始新的有限请求链 |
| continuation，工具结果或宿主任务继续 | 沿用最近成功真实模型及其思考档位，保持缓存和上下文连续性；没有 previous 时用当前索引 |
| retry，暂时性模型失败 | 根据 failed 中的真实模型和分支状态选择下一个尚未尝试的模型；更新当前索引与冷却，不在同一故障链绕回主模型 |
| retry，上下文恢复 | 沿用 failed，不当服务故障切换 |
| retry，failed 缺失 | 不猜上次用了谁，不继续换链；以明确路由错误结束并保存诊断 |
| direct，压缩或其他循环外请求 | 优先用最近成功模型，否则当前链可确定的模型；不单独选廉价模型，不写分支状态 |

链尾耗尽时返回可识别的终止错误，不再发物理请求；错误文本必须经探针确认不会被宿主再次当暂时故障。即使宿主还做路由重试，也只能得到同一终止结果，不能产生额外物理请求。宿主取消信号到达后不再选取或发起下一次请求。

冷却是对后续**真实用户新输入**的选择提示，不是定时探测。没有新输入就不切回；任务守卫的自动继续属于 continuation，保持当前模型。状态只在会话分支内共享，接受其他会话可能再次碰到主模型故障的限制；没有数据前不增加全局共享熔断。

## 必做的能力探测

使用现有网络隔离夹具，以真实 Pi 加本地假模型验证。每次显式加载本工作区插件，临时 agent 数据目录与空凭据，拒绝远程连接，保存请求顺序、会话记录与插件选择。绝不把草图可编译当成功。

1. 本地模型返回四种网关错误之一；message_end 改写后，Pi 的内建 retry 选择后继模型。
2. 原生断流、502/503 走宿主 retry；余额、鉴权和未知错误保持原文并终止，不产生备用物理请求。
3. 工具已经产生一次可计数写入后让后续模型请求失败；恢复后计数仍为一次，原工具结果仍可用。
4. 退避时取消、切会话、手动选择物理模型；旧恢复不切模型、不再发请求。使用宿主控制通道，不以内部分支 AbortController 单测替代交互接线。
5. `failed` 缺失、路由抛错、链尾、配置模型无凭据、上下文溢出等分支都有明确终局。
6. 在子代理显式扩展配置及模型允许范围中加载插件，选虚拟模型并注入故障；记录其是否真正调用后备模型，不能只检查名字解析成功。

若第 1 项不成立：插件仍可仅支持 Pi 原生暂时错误，但文档和验收必须明确网关四类未覆盖；不新增手写恢复器掩盖。若基本虚拟模型能力不可用：插件不放行，报告最低宿主要求；x-rail 单独交付。

若子代理不支持：子代理用明确物理模型；父任务按原运行活跃/终止/未知进行接收恢复。不会自动反复派新子代理模拟插件成功。宿主兼容范围首版仅声明实测过的 Pi 与 pi-subagents 版本。

## 发布与费用

首版只准备本地独立包、测试和说明；不发包、不改个人配置、不选择真实付费模型、不请求一次“健康探测”。实际安装与用户选用模型链是单独授权动作。

默认任务安装不包含此插件。组合安装前预检旧 x-failover 加载入口，发现同时活动则停止激活并报告冲突，不偷偷移走用户文件。回滚为用户授权后切回旧版本加载路径，不删除模型状态或 x-rail 任务记录。
