## 1. 验收范围与证据位置

本版先调整工作分工，不把精简摘要、跨会话恢复、并行补位和纠偏演练统一设为首批必过项。后续实施前在原实施记录中写清实际变更、必要观察与结束条件；已承诺的契约必需项继续履行，不能借本方案取消。

严格任务的验证输出进入原任务 `evidence/`，正式运行引用沿用 `audit/runs.json`，状态和下一动作只在 `state.md` 维护；恢复要点按需写 `handoff.md`。普通任务在工具结果与回复交付，不为本版另建状态。方案目录只保存设计，不放运行产物。

## 2. 首批必要验收

### 2.1 文档与规则一致性

核对实际修改的入口、执行说明和子任务模板，确认：

- 目标、范围、必要输入与验收明确且已有授权时，主会话主动交出完整执行工作；独立项可并行，有依赖项接力，不先贴“大任务”标签。
- 短小且主会话已掌握材料的工作可以直接完成，紧密耦合的实现由同一位执行者承接；普通／严格与长模式继续按原规则判断。
- 返回内容能定位真实产物、证据、偏差和下一步；主会话按缺口核验，输入或集成变化补相关检查，保留现行及契约必需独立审查。
- 范围、风险或验收变化时先调整边界；权限、费用、单写入者、原运行恢复和失败处理沿用权威来源。
- 首批不要求精简摘要或整套复杂演练；运行规则与实施前方案的状态说明准确。

静态检查只证明规则表达与引用一致，不能证明真实执行者遵守。

### 2.2 一条真实接力任务

使用一项已授权、可验证且包含前后依赖的真实工作，优先复用正常实施任务，不为每条规则新开代理。后继必须有真实目标与可观察结果；宿主或授权不足时保留此项未完成，不能用模拟代替。

| 观察点 | 通过标准 | 最小证据 |
| --- | --- | --- |
| 主动派发 | 前置满足后，主会话主动派发后继，无需用户逐项提醒 | 首次可派发事实、派发内容与时间、原运行引用 |
| 完整执行 | 执行者读取实际代码与调用方，完成范围内调查、实现、相关测试及必要修复 | 实际产物、允许路径与版本、验证命令和结果 |
| 精简交接 | 后继获得可访问的必要约定与证据，失败、偏差和未验证项明确 | 正式返回内容、产物绑定或引用、必要约定 |
| 有依据的接收 | 主会话核对真实产物和当前输入，复用仍有效证据；补读、重跑和审查分别说明解决什么缺口 | 实际接收动作、复用与新增检查依据、受集成影响的验证 |
| 按约结束 | 必修问题解决、必需验收和审查满足后交付，非阻塞建议留后续 | 原验收对照与当前证据、最终状态和未验证范围 |

使用新上下文时保存宿主实际模式；新运行标识本身不能证明历史隔离。独立副本的检查只证明当时副本，最终核对实际交付工作区的相关输入、环境和组合影响。无需追求“零补读”“零复验”，必要动作有依据即可。

## 3. 按实际变更选择的补充场景

| 实际变更或触发事实 | 补充观察 | 不需要因此做什么 |
| --- | --- | --- |
| 调整了原运行恢复或跨会话交接行为 | 真实接手原目标、继承约束并执行下一动作；输入变更能被识别 | 未改恢复机制时不强制跨会话演练 |
| 调整了并行调度或通知消费 | 用独立项及后继观察安全接收、单写入者和及时补位 | 串行接力样本不冒充并行证据，也不为首批额外造并行工程 |
| 执行中发现范围、风险或验收变化 | 观察首次可知事实后是否先调整边界并保留已有工作 | 无需为每类事件单独开代理或新增分类表 |
| 有一批同形工作，说明、环境或验收尚未跑通 | 以第一项验证说明到接收能跑通，再扩大 | 已有当前有效同类证据时不重复试跑 |
| 输入、环境或集成变化，已有证据不再适用 | 补受影响检查，核对真实交付结果 | 不因换会话或无关文档变更从头重跑全部 |
| 原契约或具体风险要求独立审查 | 对明确对象取得独立判断，修复后按原协议定向复核 | 不固定每位执行者配审查者，不叠加重复全量审查 |

选择依据合并写入原计划或下一动作，不新建巡检账本。基础设施故障按宿主协议保存准确报错与原运行，不能换协议或重复启动绕过。

## 4. 后续精简摘要的验收条件

仅在真实摘要负担取得证据、该增强获准实施后执行。本节不阻塞首批行为改进，也不表示已有可运行选项。

首版只考虑拟新增的 `summary --compact`（任务摘要精简视图）；`--item`（指定展开某一工作项）及额外前置展开继续推迟。复用现有测试入口，至少核对下列行为：

| 行为 | 通过标准 |
| --- | --- |
| 默认兼容 | 同一样本不带新选项时，原完整信息与错误边界保持兼容 |
| 重点与计数 | 正常已完成项被汇总，当前项、就绪项、状态计数与原记录相符；完整范围、权限、风险、审查、阻塞及下一步可见 |
| 全局异常 | 非当前项失败、证据过期、报告变化或必需审查缺口仍可见；原完成门仍拒绝不满足条件的任务 |
| 错误与只读 | 结构错误明确报错或标明检查未完成；正常与异常调用前后任务文件保持一致，不放宽历史解析范围 |
| 输出变化 | 同一样本记录完整与精简视图的字节量、关键事实覆盖和耗时；输出减少不当作总提速 |

先观察功能缺失导致反例失败，再最小实现并验证。使用仓库已有 Python 标准库测试，不新增框架，不为渲染重写校验器或增加跨调用缓存。

后续实施按实际修改选择已有检查入口：规则改动考虑 `bash scripts/test-flow.sh`、`PYTHONDONTWRITEBYTECODE=1 python3 scripts/test-skill-xml.py` 及 `bash scripts/check-repo.sh`；摘要增强再选择 `scripts/test-work-items.py` 与 `scripts/test-task-checks.py`。执行前先读脚本核对副作用，涉及相同临时资源时串行；契约已列为必过的检查按约完成。

保存退出码、明确通过计数、失败名称与原始输出位置；纯关键词检查不能代替真实接力、异常可见或完成门行为。未改代码的本轮不以全量代码测试代替文档核对。

## 6. 效率观察与交付判定

优先随正常执行记录用户等待、交接耗时、父子运行、主会话必要补读、复用与重跑检查、剩余缺陷，以及宿主可提供的实际用量。仅有主会话材料量时，不能代表父子运行总开销；真实费用无账单或可靠用量时写未知。

同条件对照在需要承诺具体幅度时再安排，需固定初始任务、验收、模型、思考级别、网关与环境，并取得相应授权。一个样本记为个案，多项同时变化只报告组合效果；不故意削弱对照组。首批不以额外多轮模型实验或摘要测量阻塞交付。

| 可报告结果 | 所需证据 |
| --- | --- |
| 方案文档已更新 | 四份文档内容、引用与当前范围核对结果；本轮只交付这一层 |
| 运行规则已写入 | 实际技能与模板改动及相关静态检查 |
| 主动接力已验证 | 第 2 节真实任务及简单反例的实际动作、产物和证据 |
| 摘要功能已验证 | 后续获准实施时，第 4 节自动行为检查 |
| 效率已有观察或改善证据 | 实际计时、用量、质量与限制；改善幅度依据有效对照，不能预设成功 |

首批实施完成以原实施契约及第 2 节所需证据为准；受授权或宿主能力阻塞时保留未完成状态。真实恢复、并行、摘要和效率分别报告实际执行范围，不能互相替代，也不承诺所有模型或未来任务普遍有效。
