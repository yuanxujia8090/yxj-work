## 阻塞项（先补文字，再开工）

### B1 错误分类只有总原则，缺逐条映射

- **现状**：E1 是混合桶，同时装“账号池暂无可用账号”“gateway_concurrency_limit”“INSUFFICIENT_BALANCE”“HTTP 401/403”“Server requested 90s retry delay”五类（`classify.ts:28-38`）。
- **问题**：4.4 与 DECISIONS 把“余额/鉴权”统一改停止；文件清单只写“区分余额/鉴权和可恢复服务错误”，没给每条正则的新归类与动作。
- **影响**：实施者按总原则改，会把“账号池无账号”“网关并发限流”“90s 重试提示”一起停。这些正是切备用模型最该处理的瞬时错误，本可自动恢复的运行会变成人工交接。
- **建议**：在 4.1 或 4.4 增加“现有正则 → 新类别 → 动作”逐条表。至少分三组：瞬时压力（保留现行为）、账号池/网关（保留切换）、鉴权/余额/额度（停止并交接）。

### B2 旧 run 在新完成门下的行为未定义，与守护自动续跑冲突

- **现状**：新检查器要求“无验收表不得 `done_met=true`”，同时承诺“旧运行可读、可恢复、只读兼容”。旧 run 没有 `acceptance.tsv`。
- **问题**：`guard-core.ts:35-38` 在 `doneMet=false` 且未到上限时继续续跑。旧 run 单元全 done 但无验收表 → 新门判未完成 → 守护持续自动续跑一个其实做完的旧任务，直到连续无变化才交接。
- **影响**：历史任务被反复唤醒并消耗模型请求；与“旧运行只读兼容”矛盾。测试矩阵没有这个场景。
- **建议**：明确 legacy 语义，二选一并写进 4.1：① `inspect` 返回 `schema=legacy`、按旧规则算 `done_met`，但 `finish` 拒绝，提示显式补验收；② legacy 强制 `pause/handoff`，守护不自动续跑。推荐 ①：保住旧任务正常收尾，只是不能被新标准认证。

### B3 状态机有出口断点：abandoned 依赖死锁、pause 后无法开新 run

- **现状**：`ready()` 要求依赖单元 `state=="done"`（`xr:451-458`），`abandoned` 不算 done。`pause` 保留 ACTIVE，而计划要求 `init` 拒绝替换未完成 ACTIVE。
- **问题**：① 计划明确“放弃不是完成、要把原验收关联到后继单元”，但后继单元若依赖被放弃的原单元就永远不 ready，`next` 返回 none，检查器永远 false，守护空转到 stall。② `pause` 之后没有命令能起新 run，`resume` 连命令名都没有（4.1 只说“将运行阶段改回执行”）。
- **影响**：正好落在计划最想修的两条路径（拆分/放弃、暂停/恢复）上，实施时会先撞墙再返工。
- **建议**：补三句：① 依赖判定改为“依赖单元 done，或 abandoned 且其验收已被后继单元接管”；② 新增 `xr resume --run-id --confirm`（或 `pause --resume`），写明恢复前检查项；③ `init` 允许替换**已暂停或已完成**的 ACTIVE，并规定旧指针去向（如 run 目录内 `pointer.released`）；`finish` 是否释放 ACTIVE 一并写清。

## 重要项（可与实施并行，但要有结论）

1. **“finish 与派发互斥”缺少落地机制。** 宿主派发是长时异步工具调用，文件锁无法跨整个子代理生命周期持有。建议改写为“派发代号”（dispatch epoch）：每次启动收据递增代号，`finish.json` 记录当时代号；之后出现新启动收据即判收据失效。第 7 节“终态后新派发”才可判定。
2. **收据事件来源写窄了。** 4.1 说“在工具结果事件中捕获”启动收据，但启动事实在 `tool_call` 事件（SDK `dist/core/extensions/types.d.ts` 的 `ToolCallEventBase`），查询结果才在 `tool_result`。另需定义子代理工具未安装/未调用时的“空启动清单”是否足以证明“无未核对宿主运行”。
3. **验收要求是自证的。** 写代码的代理同时写 `acceptance.tsv` 原文和 `verify_cmd`，一条 `true` 就能满足。计划承认无法自动判断语义，但没有工程约束。建议 `acceptance.tsv` 增加 `source` 列（引用用户原话/任务文件），`finish` 要求 source 非空；高风险运行把“独立审查”列为必需验收单元（计划有此意，未写进 finish 条件）。
4. **进度指纹没覆盖新状态。** `unitsFingerprint` 只拼 units+ledger（`run-files.ts:47-52`）。只改验收表或运行阶段不会被算作进展，会误触发“连续 3 次无变化”交接。建议指纹纳入 acceptance 与 phase。
5. **子代理重复计数缺机制。** 状态按 `run_id` 存，子代理共享 cwd 和 ACTIVE 时会双计 `toolCallsSinceFailover`（`x-failover.ts:71-79`）。SDK 提供 `ctx.sessionManager.getSessionId()`（`session-manager.d.ts:178`），可做会话键，建议写进 4.3 的落地方式。
6. **`--run-id` 的解析位置要写清。** 现有 `--repo` 不在 argparse 里，由 `main()` 手工剥离（`xr:997-1014`）；新增 `--run-id` 需同样处理，否则命令示例（`xr --repo X --run-id Y inspect`）实际不可用。另：`cmd_import` 内部调用 `cmd_init`，加“拒绝覆盖未完成 ACTIVE”会连带改 import 行为，需一句话说明。
