## 一句话结论

核心闭环仍为推荐范围（运行绑定 + 完成门 + 故障恢复 + 真实 Pi 本地验收）。本版把原阶段四的完成门并入核心，**预算 70% 自动收尾**拆为独立启用；真实模型回放、个人 Pi 安装不包含在默认执行中。宿主收据捕获可行性仍须先测，不凭文字规格承诺完整闭环。

## 会改动什么

不出新框架，复用现有 `xr` 与扩展，补五处接缝：

1. `skills/x-rail/scripts/xr`：新增检查、验收、完成、暂停/恢复和依赖改接命令；运行参数明确解析，验证日志唯一。
2. `extensions/run-files.ts`：完成判断改为调用 `xr inspect`，不再本地解析 TSV 猜完成。
3. `extensions/x-run-guard.ts`、`x-failover.ts`：运行绑定固定、看门狗与普通错误共用一套上限检查。
4. `extensions/classify.ts`、`switch.ts`：补断流/502；余额鉴权改默认停止；恢复提示用真实路径。
5. 测试与文档：新增 `scripts/test-run-lifecycle.mjs`、扩 `scripts/test-xr.py`、`failover.test.ts`、扩 mock 服务；同步阶段卡与验证说明。

核心新增运行材料为 `acceptance.tsv`（要求与单元的关联表）、`finish.json`（验收收据）和独立验证日志；预算方案另有可选 `budget.json`。沿用现有运行文件保存暂停与绑定信息。不迁移旧 `task.py`，不改全局模型/重试/并行配置。

## 主要风险

| 风险 | 控制 |
| --- | --- |
| 完成门过严卡住正常收尾 | 完成/明确放弃/未验证三类分别测试；历史任务只读兼容 |
| 新增 acceptance 文件不兼容 | 追加可选文件；旧表不批量迁移 |
| 自动续跑越过用户中止/权限门 | 所有恢复入口共用检查；用户中止停止；受决策门阻塞的工作不续跑，独立且已授权工作仍可推进；未知错误明确暂停 |
| 余额错误策略变化 | 作为推荐策略随实施范围评估，本轮未改变代码行为 |
| 技能软链接导致提前影响个人 Pi | 在独立 worktree 实施；不移动现有软链接 |
| SDK 无法稳定注入 | 记录阻塞，不以类型检查代替通过 |
