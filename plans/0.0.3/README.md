1. 阅读[优化目标](优化目标.md)，理解范围、取舍与完成标准。
2. 阅读[实施方案](实施方案.md)，按任务依赖逐项实施。
3. 阅读[验收与证据](验收与证据.md)，先建立反例，再修改实现。

本目录是目标项目文档。执行过程、命令输出、阶段记录和审查报告保存在执行工作区的 `.work-docs/tasks/<task-id>/`。不把过程输出复制到本目录，不覆盖其他任务记录。

## 交接时已经确定的选择

- 已按推荐选了渐进式加固，因为契约、状态、证据和安装清单可以继续复用。
- XML（Extensible Markup Language，可扩展标记语言）用于分开不同语义模块。它不承担权限控制。
- 普通任务与长任务按恢复需求区分，不再因为阶段数量多而自动升级。
- 新任务采用严格完成检查，历史记录允许只读检查；不得根据模型漏填字段自动降级为旧格式。
- 主会话和子任务都需要取证出口。文档任务先形成初稿，再补影响结论的证据。
- 新增 `x-self-check`，默认检查七日，支持三周回看；只输出有依据的建议。
- 本版本先精简加载，保留现有 33 个技能文件，再增加自检入口。预计清单为 34 项，以脚本统计为准，不以数量作为优化成绩。
- 不预先批准技能删除，不要求把技能强行压缩成 18 个。

## 版本结束时交付什么

| 交付 | 必备内容 |
|---|---|
| 改动清单 | 文件、行为变化、兼容范围 |
| 验收矩阵 | 本目录每个目标对应的检查结果及原始证据 |
| 行为对照 | 固定任务、实际加载的技能版本、模型、产物、耗时分类、局限 |
| 自检样例 | 合成数据测试结果，以及经过脱敏的真实三周分析摘要 |
| 技能取舍表 | 保留、按需加载、候选退役，逐项给依据 |
| 交接记录 | 未验证项、等待授权项、恢复所需第一步 |

付费行为试验或全局安装未获授权时，交付本地实现和可审阅材料，保留相应阻塞状态。不能为满足“全部完成”放宽验收。
